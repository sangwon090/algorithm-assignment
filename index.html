두 알고리즘의 기본 원리

구간 합은 배열에서 연속된 원소들의 합이다. 예를 들어 A = [3, 1, 4, 1]에서 [1, 3]의 합은 A[1] + A[2] + A[3] = 6이다. 배열의 값이 바뀌면 이후 조회에서도 바뀐 값을 반영해야 한다.

Naive 구간 합

배열에 원소의 값만 저장한다. 합을 구할 때는 누적 합을 0으로 놓고, 요청한 구간의 첫 원소부터 마지막 원소까지 하나씩 더한다. 같은 구간을 다시 조회해도 처음부터 계산한다.

값을 바꿀 때는 배열 한 칸만 수정하면 된다. 준비 과정과 값 변경은 간단하지만, 조회 구간이 길수록 매번 더해야 할 원소가 많아진다.

세그먼트 트리

배열의 구간을 절반씩 나누는 이진 트리이다. 맨 위의 루트는 배열 전체를, 두 자식은 왼쪽과 오른쪽 절반을 맡는다. 원소 하나가 남을 때까지 나누며, 이 마지막 노드를 리프라고 한다. 각 노드에는 자신이 맡은 구간의 합을 저장한다.

리프에 원소 값을 넣고 두 자식의 합으로 부모를 채운다. 조회할 때는 요청 범위에 완전히 포함된 노드의 합을 바로 사용한다. 일부만 겹치면 자식으로 내려가고, 겹치지 않으면 0을 반환한다. 값 변경 후에는 해당 리프와 조상들의 합만 갱신하므로, 다른 구간의 합은 계속 사용할 수 있다.

구간 합을 구할 때

배열에서 인덱스 2부터 5까지의 합을 구한다. Naive 구간 합은 원소를 하나씩 더한다. 세그먼트 트리는 여러 원소의 합을 미리 저장해 두고, 조회할 때 그 합을 가져온다.

Naive 구간 합: 구간 안의 원소를 모두 읽는다.

인덱스 2, 3, 4, 5의 값인 4, 1, 5, 9를 차례로 더한다. 구간이 길어지면 그만큼 더 많은 원소를 읽는다. 이전에 같은 구간을 계산했어도 결과를 저장하지 않으므로 다시 더해야 한다.

세그먼트 트리: 필요한 구간을 찾는다.

루트의 [0, 7]은 요청한 [2, 5]보다 넓다. 왼쪽 [0, 3]과 오른쪽 [4, 7]로 내려간다. [0, 1]과 [6, 7]은 범위 밖이므로 0을 반환하고, 그 아래는 탐색하지 않는다.

구간 전체가 포함되면 저장된 합을 쓴다.

[2, 3]의 합 5와 [4, 5]의 합 14를 더하면 19이다. 두 구간은 요청 범위 안에 완전히 들어가므로, 자식 노드의 원소를 다시 읽을 필요가 없다.

배열 전체의 합은 루트 하나로 구한다.

[0, 7]의 합을 구할 때 Naive 구간 합은 원소 8개를 모두 읽는다. 세그먼트 트리는 루트에 저장된 31을 바로 반환한다. 구간 안의 원소를 다시 더하지 않아도 된다.

값 하나를 바꿀 때

인덱스 4의 값을 5에서 8로 바꾼다. 원소 하나는 3만큼 커지고, 그 원소가 포함된 구간의 합도 3만큼 커진다.

Naive 구간 합은 배열 한 칸만 고친다.

A[4] = 8을 기록하면 끝이다. 부분합을 따로 저장하지 않기 때문에 다른 값을 수정할 필요가 없다.

변경된 원소가 포함된 경로만 갱신한다.

인덱스 4의 리프를 8로 바꾼 뒤, [4, 5]: 14 → 17, [4, 7]: 22 → 25, [0, 7]: 31 → 34로 갱신한다. 전체 15개 노드 중 이 경로의 4개만 수정한다. 나머지 구간의 합은 그대로 사용한다.

5 + 17 = 22

값이 바뀌어도 저장된 합으로 조회한다.

갱신 후 [2, 5]를 조회할 때도 두 구간의 합만 사용한다. 바뀌지 않은 [2, 3]의 합 5와 갱신한 [4, 5]의 합 17을 더하면 22이다.

핵심 코드

트리는 아래에서부터 채운다.

리프에는 배열 값을 넣고, 부모에는 두 자식의 합을 저장한다. 예를 들어 4와 1을 더해 [2, 3]에 5를 저장한다.

Naive 구간 합

sum(A, l, r):
  result = 0
  for i = l to r:
    result += A[i]
  return result

Naive 구간 합 · 값 변경

update(A, i, x):
  A[i] = x

Segment tree · 초기 구축

build(v, s, e):
  if s == e:
    T[v] = A[s]
    return
  m = floor((s + e) / 2)
  build(2*v, s, m)
  build(2*v+1, m+1, e)
  T[v] = T[2*v] + T[2*v+1]

Segment tree · 구간 합

query(v, s, e, l, r):
  if e < l or r < s:
    return 0
  if l <= s and e <= r:
    return T[v]
  m = floor((s + e) / 2)
  return query(2*v, s, m, l, r)
       + query(2*v+1, m+1, e, l, r)

Segment tree · 값 변경

update(v, s, e, i, x):
  if s == e:
    T[v] = x
    return
  m = floor((s + e) / 2)
  if i <= m:
    update(2*v, s, m, i, x)
  else:
    update(2*v+1, m+1, e, i, x)
  T[v] = T[2*v] + T[2*v+1]

비용 비교

연산 Naive 구간 합 Segment tree
초기 전처리 없음 O(n)
구간 합 O(k), 최악 O(n) 최악 O(log n)
값 하나 변경 O(1) O(log n)
전체 저장 공간 O(n) O(n)
재귀 호출 공간 O(1) O(log n)

n은 배열 길이, k = r − l + 1은 조회 구간의 길이이다. 입력 배열을 읽는 O(n) 비용은 두 방식에 공통이다.

조회 범위가 길수록 차이가 난다.

Naive 구간 합은 구간 안의 k개 원소를 모두 읽는다. 세그먼트 트리는 완전히 포함된 구간에서 탐색을 멈춘다. 각 깊이에서 부분적으로 겹쳐 더 내려가야 하는 구간은 양 끝의 최대 2개이고, 트리 높이는 O(log n)이므로 질의도 O(log n)이다.

원소 65,536개인 배열에서 [1000, 49999]를 조회하면 Naive 구간 합은 49,000개 원소를 읽는다. 세그먼트 트리는 49개 노드를 방문하고, 그중 12개의 저장된 합을 사용한다.

한 번 만든 트리를 계속 사용한다.

처음 O(n) 시간에 트리를 만들면 이후 질의마다 다시 만들 필요가 없다. 값이 바뀔 때도 리프에서 루트까지 O(log n)개 노드만 갱신한다. 긴 구간을 반복해서 조회하면서 값도 변경하는 경우, 매번 원소를 모두 더하는 비용을 줄일 수 있다.

Naive 구간 합은 별도 전처리 없이 값을 O(1)에 변경한다. 세그먼트 트리는 초기 구축 O(n)과 값 변경 O(log n)의 비용을 들여, 구간 합을 최악 O(log n)에 구한다. 트리의 노드 수가 O(n)이므로 저장 공간도 O(n)이다.
